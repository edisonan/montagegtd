# PC 端 PRD / 信息架构

## 1. 文档目标

本文档用于定义蒙太奇 PC 客户端的一期产品形态、信息架构、核心模块、关键流程与实现边界。

本文档默认前提：

- PC 端采用“复用现有后端接口，重写 PC 端前端”的主路线
- 低频页面允许阶段性内嵌 URL
- 一期目标不是覆盖全部 Web 页面，而是先做高频核心工作流

## 2. 产品定位

PC 端不是网站桌面壳，而是：

`个人工作台 + 专注台 + 阅读摘录台`

目标用户价值：

- 比网页更高效
- 比网页更适合长时间驻留
- 比网页更适合多任务并行
- 比网页更适合键盘鼠标高频操作

## 3. 一期产品目标

## 3.1 业务目标

- 提供一个值得长期打开的桌面客户端
- 优先强化任务、专注、阅读、笔记的高频联动
- 把“记录”升级为“工作流”

## 3.2 用户目标

用户可以在 PC 端完成以下主链路：

1. 打开工作台查看今天要做什么
2. 从任务直接开始专注
3. 专注完成后快速记录手账/复盘
4. 在阅读中摘录内容并沉淀到笔记
5. 用键盘、拖拽、多面板而不是频繁跳页完成操作

## 3.3 一期成功标准

- 用户能在首页完成主要日常操作，不依赖频繁打开网页端
- 任务和专注成为桌面端最常用的两个模块
- 阅读和笔记形成基本闭环
- 客户端具备至少 3 个网页端没有的高价值能力

建议至少达到：

- 悬浮专注窗
- 全局快捷键/局部快捷键
- 多面板联动布局

## 4. 产品范围

- 专注模块

- 阅读模块

## 4.2 一期建议做

- 全局搜索

## 6. 核心模块 PRD

## 7. 核心流程

## 7.1 每日执行流程

1. 用户打开工作台
2. 查看今日任务和当前进行中任务
3. 从任务直接开始专注
4. 专注完成后记录成果
5. 必要时补充笔记或复盘

### 设计要求

- 这个链路尽量不跳页
- 尽量用侧栏、弹层、小窗完成

## 7.2 阅读沉淀流程

1. 用户进入阅读模块
2. 选择分类和 feed
3. 浏览文章列表
4. 打开文章预览或详情
5. 选中文本摘录
6. 一键生成笔记或追加到已有笔记

### 设计要求

- 阅读和笔记尽量在同一工作流内完成
- 不要频繁打开新页面打断阅读节奏

## 7.3 任务整理流程

1. 用户进入任务列表或四象限
2. 过滤/搜索当前任务
3. 通过拖拽或快捷键调整优先级
4. 设置时间、开始专注、补充笔记

### 设计要求

- 任务整理强调批量和快捷操作
- 详情尽量侧栏化，不建议频繁全页跳转

## 8. 全局能力设计

## 8.1 全局搜索

搜索对象建议包括：

- 任务
- 笔记
- 手账
- 文章
- feed

目标：

- 作为 PC 高速入口，而不是页面内搜索替代品

## 8.2 命令面板

建议支持：

- 打开任意模块
- 新建任务
- 开始专注
- 新建笔记
- 打开最近文章
- 切换模式

建议快捷键：

- `Cmd/Ctrl + K`

## 8.3 通知与托盘

- 专注开始/结束提醒
- 任务提醒
- 托盘常驻
- 从托盘快速开始专注

## 8.4 快捷键体系

全局建议：

- `Cmd/Ctrl + K` 命令面板
- `Cmd/Ctrl + F` 当前页搜索
- `Esc` 关闭弹层

工作台建议：

- `Space` 开始/暂停专注
- `N` 新建任务
- `J` 打开手账录入

任务建议：

- `E` 编辑
- `C` 完成
- `1-4` 调整优先级

## 9. 交互原则

- 尽量少跳页
- 优先侧栏、弹层、小窗
- 鼠标和键盘都高效
- 长时间驻留不疲劳
- 重要状态始终可见
- 高频动作永远少于两步

三期建议重点：

- 多窗口协同

## 13. 最终建议

PC 端一期不要追求“覆盖所有网页功能”，而要追求“把最高频的五条工作流做得明显优于网页”。

这五条工作流建议定义为：

1. 打开工作台处理今天的任务
2. 从任务直接开始专注
3. 专注结束后立即补录成果
4. 阅读时直接摘录并沉淀到笔记
5. 用快捷键和侧栏完成大部分操作

如果这五条链路成立，PC 端就是一个真正有价值的产品，而不是网站外壳。
