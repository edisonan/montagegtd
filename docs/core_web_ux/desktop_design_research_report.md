# PC 端设计调研报告

## 1. 结论先行

### 1.1 推荐路线

- 不建议 PC 端长期直接“加载 Web URL”作为正式产品形态。
- 推荐采用“复用现有后端接口，重写 PC 端前端”的主路线。
- 更务实的落地方式不是一次性全重写，而是：
  - 第一阶段：用现有接口快速搭出 PC 原生工作台
  - 第二阶段：把高频核心模块做成真正的桌面化交互
  - 第三阶段：少量低频页面再考虑内嵌 URL 兜底

### 1.2 架构建议

- 最优方案是“混合模式”：
  - 核心高频模块：原生 PC 界面，直接调用接口
  - 低频后台/配置类页面：必要时内嵌 URL
- 如果二选一，我更建议“复用接口重写”，不建议“全部直接加载 URL”。

## 2. 为什么不建议直接加载 URL 为主

### 2.1 优点

- 开发快
- 复用现有页面最多
- 联调成本低
- 前后端改动最少

### 2.2 主要问题

- Web 页面不是为桌面端操作效率设计的。
- 很多能力只能“能用”，做不到“桌面产品好用”。
- 性能、窗口态、多面板、快捷键、系统级通知、悬浮窗、离线缓存这类 PC 价值点很难做好。
- 一旦你后面想做桌面差异化，URL 壳子会越来越重，最终还是要返工。

### 2.3 在你这个产品里的具体问题

你的产品不是单纯内容展示，而是明显包含：

- 专注计时
- 任务操作
- 手账记录
- 阅读摘录
- 笔记沉淀

这些都属于高频交互型工作流，不适合长期只靠嵌入网页承载。

尤其是下面这些场景，URL 模式会比较别扭：

- 专注中切纯净模式
- 悬浮番茄钟小窗
- 多窗口并行
- 键盘快捷键重度操作
- 拖拽排期和任务面板停靠
- 系统级通知与提醒
- 选中文本后桌面级摘录/AI 动作

## 3. 为什么更推荐复用接口重写

### 3.1 你真正该复用的是“能力层”，不是“页面层”

建议复用：

- 登录鉴权
- 任务接口
- 专注记录接口
- 手账接口
- 笔记接口
- 文章阅读接口
- 统计接口

不建议硬复用：

- Web 页面布局
- Web 弹窗层级
- Web 响应式结构

原因很简单：PC 端最值钱的是交互效率，不是把网页搬进去。

### 3.2 长期维护成本更低

如果做 URL 壳子：

- Web 改版会牵动 PC
- 页面脚本和桌面桥接会越来越耦合
- 出问题时不容易界定是 Web 问题还是桌面容器问题

如果做接口复用：

- 后端稳定演进
- Web 和 PC 可以各自按终端特性优化
- 业务能力共享，表现层解耦

### 3.3 更容易建立桌面产品壁垒

PC 端如果只是网页壳，用户感知不到“为什么要装客户端”。

只有当 PC 端具备下面这些独特收益，客户端才成立：

- 更快
- 更稳
- 更专注
- 更适合多任务并行
- 更适合键盘和鼠标密集操作

## 4. 最适合你的 PC 端产品定位

建议不要把 PC 端做成“浏览器里的网站镜像”，而是做成：

`个人工作台 + 专注台 + 阅读摘录台`

核心关键词：

- 高并发操作
- 长时间驻留
- 多面板联动
- 快捷键优先
- 轻跳转，重上下文

## 5. PC 端应该重点增加哪些差异化内容

## 5.1 首页工作台差异化

- 可停靠的任务侧栏
- 可拖拽调整左右栏宽度
- 可记忆布局
- 多窗口模式
- 全屏纯净专注模式
- 第二屏专注小窗
- 今日统计 mini panel

这是最值得优先做的区域，因为它直接决定客户端是否比网页更高效。

## 5.2 任务模块差异化

- 左列表右详情侧栏
- 四象限拖拽增强
- 同象限排序拖拽
- 多选操作
- 键盘批处理
- mini calendar 排期
- 截止时间临近高亮
- 任务联动最近专注/笔记/手账

任务模块是最适合桌面化的模块之一，收益很高。

## 5.3 专注模块差异化

- 悬浮番茄钟窗口
- 置顶小窗
- 任务开始专注一键联动
- 系统级倒计时提醒
- 专注完成后弹出轻量复盘卡片
- 快捷键开始/暂停/放弃/记录

专注模块天然适合桌面端，因为它需要常驻和轻干扰。

## 5.4 阅读模块差异化

- 三栏阅读布局
- 左侧 feed/分类
- 中间文章列表
- 右侧预览/摘录/AI
- 选中文本立即摘录到笔记
- 阅读与笔记分屏
- 原文网页和清洗正文双视图切换

阅读模块在桌面端最应该强调“并行阅读与沉淀”。

## 5.5 笔记模块差异化

- 列表 + 编辑器 + AI 抽屉三栏布局
- Markdown 分屏预览
- 拖拽附件
- 来源预览卡片
- 音频转写工作台
- AI 常驻侧边栏

如果笔记只是网页输入框，桌面价值不大；如果是整理中枢，价值就很高。

## 5.6 跨模块差异化

- 全局搜索
- 全局快捷键
- 系统托盘
- 常驻后台提醒
- 最近操作面板
- 命令面板
- 统一收件箱

其中最推荐优先做的是：

- 命令面板
- 全局搜索
- 系统托盘 + 悬浮专注窗

## 6. 哪些页面可以先不重写

不必所有东西第一期都原生化。

建议第一期不重写或延后重写：

- 低频配置页
- 较少使用的说明页
- 后台管理页
- 一些纯展示型静态页

这些可以先内嵌 URL，节省成本。

## 7. 推荐的技术和产品策略

## 7.1 产品策略

建议分三层：

### A 层：必须原生桌面化

- 首页工作台
- 任务列表/四象限
- 专注计时与悬浮窗
- 快速手账录入
- 文章阅读主工作流
- 笔记编辑与摘录

### B 层：可逐步桌面化

- 专注历史统计
- 手账历史整理
- 阅读批处理
- AI 辅助整理

### C 层：可暂时内嵌 URL

- 设置页
- 说明页
- 较低频的管理功能

## 7.2 前端策略

如果你已经在做 Electron 类客户端，建议：

- 建立独立 PC 路由和布局系统
- API 调用层与 Web 共用约定
- 不共用 Blade 页面
- 尽量共用接口字段和业务规则
- 在桌面容器中提供系统能力桥接

## 8. 我给你的明确建议

### 8.1 如果你想做“短期最快上线”

- 可以先做混合模式
- 但只把低频页面走 URL
- 高频核心模块一定别偷懒，全走原生 PC UI

### 8.2 如果你想做“中长期正确路线”

- 直接按接口复用、前端重写推进
- 先做首页、任务、专注、阅读、笔记这五块
- 不要先做一套几乎等同网页的 PC 客户端

### 8.3 最终判断

你的产品形态决定了：

- “直接加载 URL”适合做过渡版
- “复用接口重写”适合做正式版

所以我的建议是：

`正式方案选接口复用重写，URL 只作为低频页面兜底。`

## 9. 推荐优先级

第一优先级：

- 首页工作台
- 专注小窗
- 任务桌面化列表/四象限

第二优先级：

- 阅读三栏工作流
- 笔记整理工作流

第三优先级：

- 统计分析
- 批量处理
- 全局搜索和命令面板

## 10. 一句话总结

如果你的目标只是“让网站出现在桌面上”，加载 URL 就够了。

如果你的目标是“做一个值得安装的 PC 客户端”，那就应该复用接口重写，并把专注、任务、阅读、笔记做成真正的桌面工作台。
