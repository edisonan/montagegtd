# PC 端设计决策报告

## 1. 结论

- 主路线选 `复用后端接口 + 重写 PC 端前端`
- 辅路线选 `低频页面内嵌 URL 兜底`
- 不建议长期把 PC 端做成“网页壳”

一句话判断：

`核心高频模块原生化，低频配置页面 URL 化`

## 2. 为什么不建议直接加载 URL 为主

直接加载 URL 的优势只有一个：`快`

但它会带来 4 个长期问题：

1. 很难做出真正适合桌面端的交互效率
2. 快捷键、悬浮窗、托盘、通知、多窗口这类桌面能力会很别扭
3. Web 改版容易牵连客户端，维护边界不清晰
4. 后续一旦要做差异化，基本还得重写一遍

如果你的 PC 端只是给低频功能一个入口，URL 可以接受。
如果你的 PC 端目标是“长期打开、每天高频使用”，URL 方案不够。

## 3. 为什么更推荐复用接口重写

真正值得复用的是：

- 登录鉴权
- 任务接口
- 专注接口
- 手账接口
- 阅读接口
- 笔记接口
- 统计接口

不建议硬复用的是：

- Web 页面结构
- Web 弹层体系
- Web 响应式布局

原因很直接：

- 后端接口复用的是业务能力
- 前端重写得到的是桌面效率

这条路线更适合你这个产品，因为你的核心不是“浏览”，而是“工作流”：

- 任务执行
- 专注计时
- 阅读摘录
- 笔记沉淀
- 手账记录

这些场景都更依赖多面板、快捷键、上下文联动，而不是网页跳转。

## 4. 推荐的产品定位

PC 端不要做成网站镜像，建议定位成：

`个人工作台 + 专注台 + 阅读摘录台`

对应三条主链路：

1. 打开工作台，处理今天任务
2. 从任务直接进入专注，结束后快速复盘
3. 阅读时摘录内容，直接沉淀到笔记

## 5. 设计策略

### 5.1 首页

首页不要只是导航页，应该直接是 `工作台`。

建议结构：

- 左侧：今日任务 / 跑道 / 四象限入口
- 中间：当前专注 / 快捷操作 / 今日节奏
- 右侧：最近笔记 / 最近阅读 / 快速录入

首页的目标不是展示信息，而是 `打开就能开始干活`。

### 5.2 布局

PC 端建议优先采用：

- 双栏或三栏布局
- 固定侧栏 + 内容区 + 详情区
- 可拖拽栏宽
- 布局记忆
- 右侧详情抽屉

不建议继续沿用移动端或网页端那种频繁切页、频繁弹窗的模式。

### 5.3 交互原则

- 少跳页，多联动
- 少弹窗，多侧栏
- 少点击，多快捷键
- 少“查看页”，多“操作台”

## 6. 哪些模块应该重写

必须重写：

- 工作台首页
- 任务列表 / 四象限
- 专注模块
- 阅读模块
- 笔记模块

可以先 URL 兜底：

- 设置页
- 低频帮助页
- 一些后台管理页
- 复杂但低频的配置页

判断标准很简单：

- 高频操作模块：重写
- 低频配置模块：先 URL

## 7. PC 端应该增加的差异化内容

下面这些能力，才是用户愿意安装客户端的原因。

### 7.1 工作台差异化

- 今日跑道
- 当前最重要任务置顶
- 最近专注记录
- 最近笔记和阅读摘要
- 快捷新建任务 / 笔记 / 手账
- 今日节奏和完成率

### 7.2 任务差异化

- 左列表右详情
- 四象限拖拽
- 多选批量处理
- 键盘完成、延期、移动优先级
- 截止时间临近高亮
- 任务联动最近专注 / 笔记 / 手账

### 7.3 专注差异化

- 悬浮番茄钟
- 置顶小窗
- 托盘控制开始 / 暂停 / 结束
- 系统通知提醒
- 专注结束后直接弹出复盘卡
- 任务一键开始专注

### 7.4 阅读差异化

- 三栏阅读
- 左侧 feed 分类
- 中间文章列表
- 右侧预览 / 摘录 / AI
- 选中文本直接摘录到笔记
- 原文与清洗正文切换

### 7.5 笔记差异化

- 列表 + 编辑器 + 详情 / AI 抽屉
- Markdown 分屏
- 来源卡片
- 从任务 / 文章 / 专注自动带入上下文
- 快速整理最近摘录

### 7.6 全局差异化

- 命令面板
- 全局搜索
- 全局快捷键
- 最近操作面板
- 托盘常驻
- 多窗口

## 8. 研发建议

建议采用混合策略，而不是二选一极端方案：

### A 层：核心高频模块

直接调用接口，原生重写：

- 工作台
- 任务
- 专注
- 阅读
- 笔记

### B 层：低频页面

阶段性内嵌 URL：

- 设置
- 帮助
- 说明
- 后台类页面

### C 层：通用底座

优先统一：

- 会话管理
- 请求层
- 全局状态
- 快捷键系统
- 通知系统
- 多窗口通信

## 9. 一期上线建议

如果只做一期，建议先做这 5 件事：

1. 工作台首页
2. 任务列表 + 详情侧栏 + 搜索
3. 从任务一键开始专注
4. 悬浮专注窗 + 系统提醒
5. 阅读摘录到笔记

这样上线后，用户会明显感知到：

- 比网页快
- 比网页顺
- 比网页更适合长期开着

## 10. 最终建议

如果只能给一个明确建议，那就是：

`不要把 PC 端长期做成加载 URL 的网页壳。`

更合适的方式是：

`复用接口重写核心模块，再用 URL 兜底低频页面。`

这是成本、上线速度、长期体验三者之间最平衡的方案。
