# Tasks 现有 UX 梳理

基于 `resources/views/tasks/index.blade.php`、`priority.blade.php`、`update.blade.php` 以及共享 `components/task-update-modal.blade.php` 整理。

## 1. 页面角色拆分

- 首页右栏：极速新增和轻处理
- `index`：完整任务列表
- `priority`：四象限视图
- `update`：传统整页编辑
- `task-update-modal`：现代化弹窗编辑

说明 tasks 已经形成“轻处理 + 深处理 + 结构视图”的较完整体系。

## 2. tasks/index 列表页

### 2.1 顶部结构

- 标题、副标题
- 返回首页
- 四象限视图入口

### 2.2 状态过滤

- 进行中
- 已完成
- 已删除
- 已折叠
- 全部

每个状态都有计数 badge，说明过滤器同时承担数据概览作用。

### 2.3 搜索

- 右侧独立搜索框，用于按任务名快速过滤。

### 2.4 列表区

- 桌面端使用表格，字段为：
  - 状态
  - 更新日期
  - 任务内容
  - 优先级
  - 操作
- 移动端切为卡片流。

### 2.5 行内动作

- 添加笔记
- 编辑任务
- 标记完成

### 2.6 任务信息表达

- 状态通过 badge 表达。
- 优先级直接映射四象限语义。
- 若有父任务，会显示“父任务 -> 子任务”层级关系。

## 3. tasks/priority 四象限页

### 3.1 视图定位

- 用艾森豪威尔矩阵管理任务。
- 用户目标是重新分配优先级，而不是只看清单。

### 3.2 顶部结构

- 模式切换：工作 / 生活
- 返回首页
- 列表视图入口

### 3.3 象限说明区

- 在真正的矩阵前，先用四张说明卡解释每个象限策略。
- 这是对方法论的显性教育。

### 3.4 象限列表区

- 四个象限各自独立卡片。
- 每块都有标题和数量标签。
- 空象限也有占位提示，保持完整矩阵结构。

### 3.5 任务卡交互

- 任务支持拖拽。
- hover 时显示完成、编辑、删除按钮。
- 已完成任务会降低透明度并添加删除线。
- 拖拽跨象限会自动更新优先级。

## 4. update 整页编辑

- 使用传统表单模式。
- 字段包含：
  - 名称
  - 父任务
  - 优先级
  - 提醒时间
  - 截止时间
  - 状态
  - 是否置顶
  - 模式
- 整页编辑更基础，视觉风格比弹窗版本旧。

## 5. 共享任务编辑弹窗

### 5.1 定位

- 是当前更现代的任务编辑体验。
- 在首页、列表页、四象限页都可复用。

### 5.2 体验特点

- 大点击面积单选卡
- 顶部/底部固定
- 内容区滚动
- 自动聚焦
- 错误区集中展示

### 5.3 字段分层

- 基础信息：名称、父任务
- 决策信息：优先级、状态
- 时间信息：提醒、截止
- 组织信息：置顶、模式

## 6. 现状 UX 特征总结

- tasks 模块是整个系统最成熟的执行管理模块之一。
- 同时提供列表式、矩阵式、嵌入式三种处理场景。
- 与 notes、index、journals 的联动已经体现在入口层。
