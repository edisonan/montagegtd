# Core Web 跨模块 UX 模式

## 1. 页面骨架

- 普遍采用卡片式信息分区，主要容器为 `max-w-7xl` 或居中窄栏阅读宽度。
- 顶部通常包含标题、副标题，以及“返回首页 / 切换视图 / 次级功能入口”。
- 桌面端偏向双栏、表格、横向工具条；移动端会回退为单栏卡片流。

## 2. 组件化交互

- 多个页面通过共享弹窗承接编辑动作，例如任务编辑弹窗、手账创建弹窗、AI 提问弹窗。
- 弹窗普遍具有：
  - 遮罩层关闭
  - 居中浮层
  - 顶部标题栏
  - 底部固定操作栏
  - 打开后自动聚焦首个输入项
  - 内容区独立滚动

## 3. 数据加载状态

- 列表页普遍具备三态：加载中、空状态、有内容。
- 空状态一般包含图标、解释文案和回流入口。
- 统计数字通常放在卡片顶部或列表上方，帮助用户先形成全局判断再进入逐条处理。

## 4. 桌面端与移动端差异

- 桌面端更多使用：
  - 表格
  - hover 显示操作按钮
  - 固定侧栏
  - 横向过滤器和工具条
  - 多列布局
- 移动端更多使用：
  - 卡片堆叠
  - 操作按钮显性化
  - 工具条换行
  - 内容折叠与短文案

## 5. 视觉语言

- 颜色承担语义：蓝色偏默认操作，绿色偏完成/成功，红色偏危险或高优，橙色偏重要，灰色偏次要。
- 大量使用渐变头部和轻投影，强调“功能区块”而非纯表单。
- 状态经常同时用图标、颜色、标签三种方式表达，冗余度较高，利于快速识别。

## 6. 可复用设计规则

- 若目标端支持 hover，应保留“行内操作在 hover 时显现”的轻量处理方式。
- 若目标端不支持 hover，应将关键操作前置或常驻显示，避免操作发现性下降。
- 所有时间型对象都适合保留“快速设定 + 精确输入 + 时长反馈”的组合方式。
- 内容型模块普遍适合“预览 + 展开 + 详情页”三层结构，而不是一次性全展开。
