# 学习计划页交互优化 Spec（v1）

> 页面：`/study`（resources/views/study/index.blade.php + StudyService + Api\V2\StudyController）
> 目标：解决"创建入口重复、无编辑能力、日期导航弱、任务无单条操作、统计信息单薄"等交互问题。
> 原则：界面简化优先、不改动数据模型的主干（复用 Plan/Task/StudyCheckin/StudyFocusSession）、所有破坏性操作有确认。

## 一、现状问题（本 spec 依据）

1. **创建入口重复**：工具行同时有「快速创建计划」「高级创建」两个按钮（同一接口、字段多寡不同），且空状态里又渲染一个「快速创建计划」——按钮出现 3 次、入口 2 种，用户无法区分。
2. **创建无引导、无反馈**：默认以"当前时刻"为起点、SP=0、内容为空；14 天任务静默生成，toast 只说"已生成任务"，用户不知道生成到哪天。
3. **计划不能编辑**：改时间/SP/内容只能停用再删除重建。
4. **日期导航弱**：周条只显示选中日所在自然周；无"回到今天"；任务列表上方无明确日期标题；周条无任务密集度提示。
5. **任务无单条操作**：生成的任务不能删除/改期，某天不想做只能停用整个计划。
6. **任务卡文案与信息**：「开始挑战」实为打开打卡表单，语义误导；SP=0 显示"金币 x0"无意义；科目 tag 靠猜（仅识别 语文/英语）；已打卡任务可无提示重复提交覆盖。
7. **统计单薄**：概览悬浮卡只有今日专注/预估/金币/能量球，无本周完成率、连续打卡天数。
8. **移动端**：任务卡操作按钮行易挤。

## 二、改动清单

### A. 创建流程统一（前端为主）
- A1 合并两个创建入口→一个「新建计划」按钮；空状态按钮同步指向统一弹窗。
- A2 统一弹窗（改造现有 planModal）：
  - 顶部：计划名称 + 模板快捷选择（不重复/每天/每周/艾宾浩斯，选了即联动"重复策略"与"每周重复日"）。
  - 「开始日期」（默认今天，作为生成任务起点，替代默认"当前时刻"）。
  - 「更多设置」折叠区：固定内容/内容类型、SP 积分、预计时长、按重复策略自定义内容与时长、每周重复日、重复策略下拉（手动微调）。
- A3 创建成功反馈：toast 显示「已生成 N 个任务（X 至 Y）」，来自后端 createPlan 返回值（plan.start_time、count）。

### B. 计划可编辑（前端 + 后端）
- B1 后端新增 `PUT /api/v2/study/plans/{plan}`：校验用户与 plan_type='study'；更新 名称/内容/开始时间/重复策略/重复日/SP/内容与时长的 fixed/by_repeat 配置（meta）。**编辑不重建已生成任务**（用户可另行点"生成任务"补未来）。
- B2 前端：计划列表每条加「编辑」；打开同一统一弹窗进入编辑模式（回填现值、标题改"编辑计划"、提交走 PUT）；保存后刷新列表与详情。
- B3 计划详情显示 `last_generated_date`（下次生成起点提示）。

### C. 任务单条操作（后端 + 前端）
- C1 后端新增 `DELETE /api/v2/study/tasks/{task}`（学习任务专用）：校验 mode=3 + 归属 → 硬删除；返回该任务是否已有打卡（供前端确认文案）。
- C2 后端新增 `POST /api/v2/study/tasks/{task}/reschedule`：改期（study_scheduled_date + planned_start/end 按天数差平移）；若同一计划目标日期已存在任务则报错。
- C3 前端任务卡加「删除」（已有打卡时确认文案说明：删除后该打卡记录在打卡列表仍保留，任务名显示为空）与「改期」入口（小弹出：选新日期，POST reschedule）。
- 取舍说明：删除为硬删除；打卡记录（study_checkins）不受影响但关联任务名会显示为空，可接受并在文案提示。

### D. 日期导航与周条增强（前端 + 后端）
- D1 工具行增加「今天」按钮 → 回到今日；「上一周/下一周」翻周按钮（选中该周周一）。
- D2 任务列表上方加日期标题：`M月D日 周X（今天/未来/过去）`。
- D3 后端 overview：days[] 每项增加 `task_count`、`checkin_count`（本周每日有任务/已打卡标记）；周条日期格显示密度小点（有任务灰点、已打卡绿点）。
- D4 保留"只看未打卡"筛选开关（默认关，开启后隐藏已打卡任务）。

### E. 任务卡文案与信息（前端）
- E1 「开始挑战」→「去打卡」；已打卡任务的打卡按钮文案为「改打卡」，卡片内提示"再次提交将更新当日打卡内容"。
- E2 SP<=0 时隐藏"金币 x0"。
- E3 取消"猜科目"标签：改为统一小标签（按重复类型显示 单次/每天/每周/艾宾浩斯），不再误导。
- E4 移动端：任务卡操作区 flex-wrap，窄屏换行不溢出。

### F. 概览与统计（后端 + 前端）
- F1 后端 overview dashboard 增加：
  - `week_total_tasks` / `week_done_tasks`（本周任务总数 / 本周已打卡数）
  - `streak_days`（连续打卡天数；今天未打则从昨天起算，今天打卡后仍续）
- F2 概览悬浮卡增加「本周完成率 x/y」与「连续打卡 N 天」，并加「打卡日历」链接行。

## 三、接口契约变化

| 接口 | 方法 | 入参 | 出参（result） |
| --- | --- | --- | --- |
| /api/v2/study/plans/{plan} | PUT | 同 createPlan 校验字段 | plan |
| /api/v2/study/tasks/{task} | DELETE | - | task_id, checkin_kept |
| /api/v2/study/tasks/{task}/reschedule | POST | date (Y-m-d) | task |
| /api/v2/study/overview | GET | date（不变） | days[].task_count/checkin_count；dashboard 增 week_total_tasks/week_done_tasks/streak_days |

## 四、明确不做（本期范围外）

- 不做月份/周历视图（周条翻周够用）。
- 不做仪表盘/统计专页（数据已在概览卡呈现）。
- 不做计划"下一次生成日期"的自动排程可视化。
- 不改动打卡页 /study/checkins 与专注页（已在上轮优化）。
- 不新增数据表。

## 五、验收标准

1. 页面无「快速创建计划」「高级创建」字样残留；仅一个「新建计划」入口。
2. 新建计划：模板联动、开始日期生效、toast 显示生成任务数与日期范围。
3. 编辑计划：回填正确、PUT 保存后列表/详情更新。
4. 任务删除/改期：确认、接口校验（非本人/非学习任务 403）、打卡存在时有提示。
5. 周条翻周、回到今天、日期标题、任务密度点正常。
6. 概览卡显示本周完成率与连续打卡。
7. php -l、Blade 编译、内联 JS 语法检查全过。

### 6.2 改完后的二次复盘（深想）

**已验证成立的判断**
1. "快速创建/高级创建"双入口确实是最大的认知负担来源——合并后创建相关按钮从 2 个变 1 个，主流流程（起名→选模板→默认今天→保存）4 步内完成。
2. "开始时间默认当前时刻"是隐藏坑：现在默认今天并明确文案"生成任务的起点"，误生成概率大降。

**改完才发现的新问题（下一步候选）**
1. **计划停用后任务仍留在日历**：停用只影响"未来生成"，已生成未打卡的任务照常显示。取舍：停用保留历史任务（打卡闭环），但建议在计划管理里提示"停用后已生成任务仍会显示，可在任务卡直接删除"。
2. **改期撞期只对"同一计划"校验**：不同计划同日撞任务暂允许（可能是有意安排）。
3. **已打卡任务删除后打卡列表任务名变空串**：可接受但观感一般；后续可在打卡列表回退显示"（已删除任务）"占位。
4. **编辑不作用于已生成任务**：改名称/SP 只对之后新生成生效（避免历史漂移），建议编辑弹窗加一行说明，避免误解。
5. **连续打卡口径**：今天未打卡从昨天起算（宽松连续），若期望严格连续需再调。
6. **模板"每周"默认=每周起始星期几**：未选重复日时按开始日星期几循环，建议模板描述写明。

**范围外但值得记档**：任务"跳过/补做"语义、周密度点 hover 提示、计划"下次生成日期"提醒，留待后续迭代。
